# Структура приложения

Приложение использует FSD. Импорты идут сверху вниз:

`app → pages → widgets → features → entities → shared`

| Слой | Содержимое |
|---|---|
| `app` | Маршруты, провайдеры, глобальные стили |
| `pages` | Отдельные страницы и их собственные preview |
| `widgets` | Header, hero, showcase, навигация документации, блоки статьи |
| `features` | Playground, поиск в документации, выбор темы и языка |
| `entities/documentation` | Описания компонентов, API, примеры кода, каталог и функции работы с ними |
| `shared` | Редактор кода, общие блоки документации, локализация, настройки и ресурсы |

## Где менять страницу

Для Input:

- `src/pages/input/ui/InputPage.tsx` — состав и порядок секций, оглавление.
- `src/pages/input/ui/InputPreview.tsx` — живой пример и применение свойств.
- `src/entities/documentation/model/components/input.ts` — описание, API, код примера и сведения о доступности.

У остальных компонентов такая же структура. Страницы экспортируются через `index.ts` своего слайса. Маршруты перечислены явно в `src/app/router/AppRouter.tsx`.

Страница сама выбирает общие блоки из `widgets/component-documentation`. Их можно переставлять, заменять и дополнять собственными компонентами. `DocumentationLayout` принимает содержимое, header и список секций оглавления.

Новую секцию можно добавить прямо в JSX страницы:

```tsx
import { Text } from '@rikkora/ui';
import { DocumentationSection } from '@/shared/ui/documentation';

<DocumentationSection id='validation' title='Валидация'>
  <Text>Содержимое секции.</Text>
</DocumentationSection>
```

Добавьте тот же `id` и локализованную подпись в массив `sections` этой страницы, чтобы секция появилась в оглавлении.

Живой пример и отображаемый код редактируются отдельно. После изменения поведения примера обновите `usage` в описании компонента.

## Правила импортов

Внутри слайса используйте относительные импорты. Между слоями обращайтесь к публичному `index.ts`:

```tsx
import { inputDoc } from '@/entities/documentation';
import { DocumentationLayout } from '@/widgets/documentation-layout';
```

Слайсы одного слоя не импортируют друг друга. Их объединяет вышележащий слой. Например, страница передаёт `SiteHeader` в `DocumentationLayout` через проп `header`.

ESLint проверяет направление импортов, независимость слайсов и использование публичных API. В `shared` код сгруппирован по технической роли; отдельных бизнес-слайсов там нет.

`src/main.tsx` — точка входа Vite. `src/testing` содержит отдельные тестовые стенды и не импортируется приложением.
